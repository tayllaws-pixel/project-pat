# Security model (v0.1)

## Threat model
- **T1 Autonomous code goes wrong** (bug, prompt injection via a dependency README, model hallucination): contained to
  forge VM (kernel isolation, LAB bridge, no LAN/tailnet, no production secrets, synthetic data only).
- **T2 Wade attempts a privileged action**: Wade has no Proxmox token, no sudo, no SSH to the host; every privileged
  operation needs a Sentinel-signed, payload-bound, single-use token verified by the executor (ADR-0005). Tested:
  `tests/test_sentinel.py`.
- **T3 Wade tampers with controls**: Sentinel runs in its own CT with its own DB role; Wade's DB role has no grants on
  the `sentinel` database; the e-stop is also a file in Sentinel's filesystem; audit is hash-chained.
- **T4 Remote attacker**: no public ports; PVE UI/SSH only from LAN + tailnet; sshd key-only; fail2ban; per-guest
  inbound DROP. Pat's gateway (phase 3) terminates TLS on the tailnet only.
- **T5 Hypervisor root / physical access** (spec §25): *not* defended by application permissions. Whoever has root
  on the Proxmox host can read every guest disk. Family-privacy guarantees are therefore against *application*
  administrators and other users, not against the host administrator. Full-disk encryption of the NVMe would protect
  data at rest when powered off, at the cost of an unlock step at every boot — offered as an option in Phase 10.

## Secrets
Generated by `patctl` step `secrets` into `/etc/project-pat/secrets.env` (0600, root) and pushed into each guest's
`/etc/project-pat/` with only the variables that guest needs. Never in git. Rotation = delete + `patctl repair --step secrets`
+ redeploy of consumers (procedure to be written with Phase 2 service steps).

## Known gaps at v0.1 (tracked)
- Service-to-service mTLS: planned (PAT-031 follow-up). Initially shared bearer tokens per pair over the LAN bridge.
- Pat authentication (PAT-028) not yet implemented; Open WebUI is **not** installed as an interim because it would
  need its own auth hardening — Pat's API comes first.
- Supply chain: pinned versions in `pyproject.toml`; `pip-audit` in CI once CI exists.
